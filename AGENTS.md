# Run Escape - Multi-Agent Operating Instructions & Handoff Protocol

## 1. Mandatory Agent Workflow (Read & Write Protocol)
Every automated agent or contributor assistant (Antigravity, Jules, Claude Code, Cursor, Copilot) working in this repository MUST follow these steps:

1. **Pre-Flight Read**: Before modifying any files or resolving a merge, read:
   - [`docs/AGENT_NOTES.md`](./docs/AGENT_NOTES.md) for the latest cross-agent handoff log, active bundle hashes, and custom hook locations.
   - [`.jules/sentinel.md`](./.jules/sentinel.md) for historical security findings and invariants in [`server/serve.py`](./server/serve.py).
   - [`docs/MULTIPLAYER_ARCHITECTURE.md`](./docs/MULTIPLAYER_ARCHITECTURE.md) when modifying WebSocket relay or Co-Op simulation logic.
2. **Upstream-Friendly Architecture & Feature Placement Rules**:
   To keep merges from `upstream/main` (`https://github.com/Dynrothe/Run-Escape.git`) conflict-free, all new features and modifications MUST follow these modular boundaries:
   - **Custom Content & Array Overrides (`src/game/content/custom/`)**: Add custom adventurers (`customCharacters.ts`), custom maps (`customMaps.ts`), custom enemies/bosses (`customEnemies.ts`), secret codes (`secretCodes.ts`), and in-place overrides to upstream content arrays (`customOverrides.ts`) inside [`src/game/content/custom/`](./src/game/content/custom/). Link them into upstream files (`characters.ts`, `maps.ts`, `enemies.ts`, `items.ts`, `passives.ts`, `shop.ts`, `quests.ts`, `weapons.ts`, `GameClient.ts`) via a single `applyCustom*(...)` or spread line so upstream content arrays remain verbatim.
   - **Custom Simulation & Save Logic (`src/game/core/custom/`)**: Place custom simulation systems (`pickupRecovery.ts`, `customSimHooks.ts`) and custom save/Armoury helpers (`customSave.ts`) in [`src/game/core/custom/`](./src/game/core/custom/) and invoke them via 1-line delegation hooks in `Sim.ts` and `save.ts`.
   - **Custom Client & Worker Helpers (`src/game/client/custom/`, `src/mapviewer/worker/customNpcIcon.ts`)**: Place custom 3D actor/dog rendering and Co-Op event resolution helpers in [`src/game/client/custom/dogActors.ts`](./src/game/client/custom/dogActors.ts) and custom negative-ID NPC item icon rendering in [`src/mapviewer/worker/customNpcIcon.ts`](./src/mapviewer/worker/customNpcIcon.ts).
   - **Custom UI Components (`src/game/ui/`)**: Place custom screens, modals, settings controls, or tables in standalone files under [`src/game/ui/`](./src/game/ui/) ([`LeaderboardScreen.tsx`](./src/game/ui/LeaderboardScreen.tsx), [`CoopGameOverSection.tsx`](./src/game/ui/CoopGameOverSection.tsx), [`CustomSettingsControls.tsx`](./src/game/ui/CustomSettingsControls.tsx)) and render them with a 1-line component tag in `GameUi.tsx`. Avoid adding large inline JSX blocks to `GameUi.tsx`.
   - **Custom Runtime Scripts & Assets (`src/custom/`)**: Edit hand-authored runtime scripts (`multiplayer.js`, `multiplayer/mp-*.js`, `cooks-assistant.js`, `tile-coords.js`, `debug-mode.js`) and custom assets (`prayer/*.png`, `quest-complete.ogg`) in [`src/custom/`](./src/custom/). Running `npm run build` automatically copies `src/custom/` into `assets/` (excluding `*.test.*`) and synchronizes `?v=X.Y` query strings via [`scripts/sync_dist.cjs`](./scripts/sync_dist.cjs). Put multiplayer unit tests in [`src/custom/multiplayer/multiplayer.test.ts`](./src/custom/multiplayer/multiplayer.test.ts).
   - **Typed Global Bridge (`src/game/types/globals.d.ts`)**: Declare any global `window.*` hooks connecting `src/game/` and `src/custom/` in [`src/game/types/globals.d.ts`](./src/game/types/globals.d.ts) instead of scattering untyped `(window as any)` casts.
   - **Separated Changelogs & Untouched Upstream Files**: Never edit root [`CHANGELOG.md`](./CHANGELOG.md), [`docs/DEVELOPMENT.md`](./docs/DEVELOPMENT.md), or [`package-lock.json`](./package-lock.json) unless syncing directly from `upstream/main`. Put all custom edition notes in [`docs/CHANGELOG.md`](./docs/CHANGELOG.md) (`src/game/ui/changelog.ts` combines `docs/CHANGELOG.md` + root `CHANGELOG.md` automatically). Keep LF (`\n`) line endings as enforced by [`.gitattributes`](./.gitattributes).
3. **Post-Task Handoff Note & Live Changelog Update**: Before finishing any task, commit, or pull request:
   - Update [`docs/CHANGELOG.md`](./docs/CHANGELOG.md) to reflect all custom changes, then run `npm run build` so `docs/CHANGELOG.md?raw` is compiled into the production bundle.
   - Prepend a new entry under `## 3. Chronological Agent Handoff Log` in [`docs/AGENT_NOTES.md`](./docs/AGENT_NOTES.md) using the template defined in that file.
4. **Source-First Build & Cache-Busting Synchronization**:
   - Edit the unminified source under [`src/`](./src/) rather than editing compiled bundles in `assets/index-*.js` directly.
   - Run `npm run build` (`vite build && node scripts/sync_dist.cjs`), which compiles `src/` into `dist/`, copies `src/custom/` into `assets/`, and automatically synchronizes `assets/index-*.js`, `assets/MapViewerApp-*.js`, `assets/RenderDataWorker-*.js`, `assets/module-*.js`, [`index.html`](./index.html), and [`assets/multiplayer.js`](./assets/multiplayer.js) with the active `?v=X.Y` cache-busting query string.

## 2. Guidelines for Fast Merges
- **Source-Based Upstream Merges (`upstream/main`)**: Pull upstream source changes from `https://github.com/Dynrothe/Run-Escape.git` (`git fetch upstream && git merge upstream/main` or `npm run sync-upstream`), resolve any TypeScript conflicts in `src/`, and run `npm test && npm run build`.
- **Parallel Subagent Chunking**: Whenever a task spans multiple files or domains, split it into small, parallel subagents with disjoint file ownership. Never emit a >20 KB file in a single `write_file` tool call; instead, write a compact (<10 KB) Node/Python transformation script or edit targeted regions with `edit_file`.
- **Verification**: Always run `npx tsc --noEmit`, `npm test`, `python -m unittest server/test_serve.py`, and `node --check src/custom/multiplayer.js` before finalizing any merge or commit.
